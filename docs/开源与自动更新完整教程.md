## 1. 建 GitHub 仓库（2 分钟）

1. 打开 <https://github.com/new>。
2. **Repository name** 填 `learning-os`；**Owner** 选 `potatob26`。
3. 可见性选 **Public**（私有仓库匿名 API 查不到，自动更新不工作）。
4. **不要**勾选「Add a README / .gitignore / license」——我们已经有这些文件。
5. 点 **Create repository**。

建好后仓库地址应当是：

```text
https://github.com/potatob26/learning-os
```

## 2. 推送「干净历史」的代码（不要推当前私有仓库）

> 为什么要另建一份：当前私有仓库的 git 历史里有旧签名口令、真机序列号、本机路径。
> 直接 `git push` 会把历史一起公开。`D:\LearningOS-public` 是只含当前代码树的全新仓库。

### 2.1 确认导出目录

```powershell
cd <导出目录>
git log --oneline          # 应该只有一条：初始开源快照
git status                 # 应该是干净的
```

### 2.2 关联远程并推送

```powershell
git remote add origin https://github.com/potatob26/learning-os.git
git branch -M main
git push -u origin main
```

第一次 push 会要求登录：用浏览器登录 GitHub 即可（或用 Personal Access Token）。

> 如果提示仓库非空（比如建仓库时手滑勾了 README），先把远程 README 拉下来合并，
> 或者删掉远程仓库重建一个空仓库。**不要**用 `git push --force` 去覆盖。

### 2.3 以后代码更新怎么同步

在私有仓库改完、提交后，重新导出再推送：

```powershell
# 在私有仓库根目录
Remove-Item -Recurse -Force <导出目录>   # 确认路径无误！
node scripts/export-public-repo.mjs D:\LearningOS-public

cd <导出目录>
git remote add origin https://github.com/potatob26/learning-os.git
git push -u origin main
```

## 3. 发布 v1.4.3 Release（5 分钟）

Release 是自动更新的数据源：App 查 `releases/latest`，读 tag 和 `.apk` 资产。

### 方式 A：网页操作（推荐）

1. 打开 `https://github.com/potatob26/learning-os/releases/new`。
2. **Choose a tag**：输入 `v1.4.3` → 点「Create new tag on publish」。
3. **Target**：`main`。
4. **Release title**：`v1.4.3 · 进入软件自动检查更新`。
5. **Description**：把 `docs/UPDATE-v1.4.3.md` 的内容粘进去。
6. **Attach binaries**：上传这些文件（在 `release/v1.4.3/` 下）：
   - `LearningOS-v1.4.3.apk` ← **必须**
   - `LearningOS-v1.4.3-source.zip`（可选）
   - `LearningOS-v1.4.3-web.zip`（可选）
   - `SHA256SUMS.txt`（建议）
   - `下载说明.md`（建议）
7. 确认没有勾「This is a pre-release」。
8. 点 **Publish release**。

### 方式 B：命令行（装了 GitHub CLI 的话）

```powershell
cd <私有仓库目录>
gh release create v1.4.3 `
  release/v1.4.3/LearningOS-v1.4.3.apk `
  release/v1.4.3/LearningOS-v1.4.3-source.zip `
  release/v1.4.3/LearningOS-v1.4.3-web.zip `
  release/v1.4.3/SHA256SUMS.txt `
  release/v1.4.3/下载说明.md `
  --title "v1.4.3 · 进入软件自动检查更新" `
  --notes-file docs/UPDATE-v1.4.3.md
```

### 发布后自检

```powershell
# 用匿名 API 看 latest 是否返回 v1.4.3 和 apk
curl.exe -s https://api.github.com/repos/potatob26/learning-os/releases/latest
```

要能看到 `"tag_name": "v1.4.3"`，且 `assets` 里有 `LearningOS-v1.4.3.apk`。

## 4. 手机安装 1.4.3（第一次必须手动）

1. 把 `LearningOS-v1.4.3.apk` 传到手机（数据线 / 微信文件 / 网盘都行）。
2. 点击 APK，系统提示「允许安装未知来源应用」——同意。
3. 因为是同一份签名 + 更高 versionCode，可以直接**覆盖安装，学习数据保留**。
4. 打开 App → 设置 → 数据，确认版本是 **1.4.3 / versionCode 45**。
5. 启动时不会弹更新（因为当前最新就是 1.4.3），这正常。

> 如果覆盖安装失败：检查是不是装过别的签名版本（需卸载重装，但会清数据，先导出备份），
> 或 versionCode 没升上去。不要为了装上而降低 versionCode。

## 5. 以后发新版本（每次 10 分钟）

```powershell
cd <私有仓库目录>

# 1) 升版本（会同时改 package.json 和 android versionCode/versionName）
node scripts/release.mjs 1.4.4

# 2) 改更新文案（App 内公告）与 docs/UPDATE-v1.4.4.md
#    编辑 src/components/updates/ReleaseNotes.tsx

# 3) 构建 APK（仓库名要写死进包，改名必须重新构建）
$env:VITE_TARGET='android'
$env:VITE_GITHUB_REPO='potatob26/learning-os'
npm run build
npx cap sync android
cd android; .\gradlew.bat assembleRelease --no-daemon; cd ..
Copy-Item android\app\build\outputs\apk\release\app-release.apk release\LearningOS-v1.4.4.apk

# 4) 跑测试（可选但建议）
npx tsc -b
node scripts/test-github-update.mjs
node scripts/test-update.mjs

# 5) 发 Release：tag 必须写成 v1.4.4，资产里放 APK
gh release create v1.4.4 release/LearningOS-v1.4.4.apk --title "v1.4.4" --notes-file docs/UPDATE-v1.4.4.md
```

已安装 1.4.3（或更早的、构建时带仓库地址的版本）会在启动后 6 小时内自动发现 1.4.4，
弹「发现新版本」；点「下载并安装」→ 浏览器下载 → 系统安装器确认。

**发版硬规则**：
- tag 必须是 `vX.Y.Z`（三段数字），否则版本比较会失败、不提示；
- Release 里必须有一个 `.apk` 资产（取第一个）；
- 版本号必须比手机上装的高（语义化版本，如 1.4.10 > 1.4.9）；
- **不要改仓库名/用户名**——改了自动更新就 404，得重新构建 App。

## 6. 自动更新的原理与边界

- **什么时候查**：每次打开 App、且距上次检查 ≥ 6 小时；失败静默，不打扰。
- **查什么**：`https://api.github.com/repos/potatob26/learning-os/releases/latest`，
  只读 tag、Release 正文、`.apk` 资产地址；**匿名、不带 token、不带学习数据**。
- **比较方式**：语义化版本（1.4.10 > 1.4.9），不是字符串比较。
- **同一版本只提醒一次**：点「以后再说」后，直到出现更新版本才再提。
- **安卓不能静默安装**：侧载 App 没有商店权限，只能提示 + 跳浏览器下载，系统安装器确认。
- **GitHub API 限制**：匿名 60 次/小时/IP；6 小时节流后一天最多 4 次，完全够用。
- **仓库必须公开**：私有仓库匿名 API 返回 404，自动更新不工作。
- **Web 版**：浏览器里走 GitHub 的 CORS，可用；数据存各自站点的 IndexedDB，与 APK 不互通。

## 7. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 打开 App 没有更新提示 | ① 仓库里没有比当前新的 Release；② 仓库是 Private；③ 仓库名不是 `potatob26/learning-os`；④ 6 小时内已查过；⑤ 该版本点过「以后再说」 |
| 提示了但按钮是「暂无下载地址」 | Release 里没有 `.apk` 资产，或资产名不是 `.apk` |
| 下载后安装失败 | 包签名不一致（装过别的签名版本，需卸载重装并先备份）；versionCode 没增大 |
| 更新后数据没了 | 正常覆盖安装不会丢；卸载重装会丢。更新前先在「设置 → 数据」导出备份 |
| `curl` 查 API 返回 404 | 仓库未公开 / 用户名仓库名不对 / 还没发布 Release |
| Release 页显示但 App 查不到 | 发布的是 pre-release？取消 pre-release；或 tag 不是 `vX.Y.Z` |
| 想换仓库地址 | 修改构建参数 `VITE_GITHUB_REPO` 后重新构建 APK；已安装的旧版无法自己改 |
