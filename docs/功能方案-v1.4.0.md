## 2. 第一批：1.4.0

### 2.1 火花（连续学习天数 + 断签挽救）

**现有口径**（不改）：每天学习 ≥10 分钟算一个学习日；今天还没学不算断；当前连续与历史最长都由 `sessions` 现算（`src/lib/stats.ts:87-133`，`computeStreaks`）。

**一处必须先承认的产品现状**：
- 首页火焰徽章点了跳「设置」（`src/components/home/HomeCards.tsx:56-66` 的 `onOpenSettings`），语义不对；
- 断签后 `streak = 0`，首页**什么都不显示**（`streak > 0` 才渲染徽章）；
- 统计页把 0 说成「未开始」（`src/pages/Stats.tsx:214-218`），对断签的人不准确。

**挽救规则（已拍板：两日修复 + 显式确认）**

1. 只救**恰好缺一天**的缺口；缺 ≥2 天不可救。
2. 缺口前至少连续 **3 天**（避免「刚连续 1 天断了也救」）。
3. 缺口后 **3 个自然日内**有**连续 2 天**，每天学习 **≥20 分钟**（计时与手动补录都算，`Session.source` 不改）。
4. 用户**手动点「接回」**才生效；不自动把数字改回去。
5. 距离上次接回 ≥**14 天**；同一个缺口日只能救一次；不能连续救。
6. 接回只写「账本」：**不生成 Session、不增加学习时长**；缺口日仍不算学习日，UI 明确标注「含 1 天缺口已接回」。
7. 若缺口日后来手动补录了真实记录 → 账本自动失效，按真实连续重算（防双算）。
8. 先给一条不需要新功能的路径：**缺口那天其实学了、只是忘了计时** → 现有手动补录可补任意过去日期（`src/components/timer/ManualEntrySheet.tsx`），补完连续自然接上；文案里引导用户先想这件事。

**状态机**（新 `src/lib/streak.ts`）：

| 状态 | 条件 | 首页徽章 | 弹层文案要点 |
|---|---|---|---|
| `empty` | 从没有学习日 | 不显示 | 今天学满 10 分钟就有了第一天 |
| `active` | 今天 ≥10 分钟 | 火焰 + 数字 | 今天已记录 N 分钟 |
| `pending` | 今天没学、昨天学了 | 火焰 + 数字 | 今天还没记录；昨天学过，连续还在 |
| `restorable` | 只缺昨天且满足前段 ≥3 天 | 灰色火焰 + 小圆点 | 昨天没记录；今天学满 20 分钟、明天再学 20 分钟可接回 |
| `repairing` | 已满足 1 天 | 火焰 + `1/2` | 接回中：今天 23 分钟（1/2） |
| `ready` | 两天都满足，待确认 | 火焰 + 小圆点 | 两天都够了；接回后是 N 天，缺口日不算学习时间 +「接回」按钮 |
| `broken` | 缺 ≥2 天 / 冷却中 / 缺口前不足 3 天 | 安静不显示 | 这次断了两天，接不回来了；今天学满 10 分钟重新开始 |

**数据模型**（顶层字段，不进 `settings`）：

```ts
interface StreakRescue {
  id: string;
  gapDay: string;          // 缺口日 yyyy-MM-dd
  beforeGapDay: string;    // 缺口前连续段的最后一天
  repairDays: string[];    // 缺口后用于接回的真实学习日（≥2）
  restoredFrom: number;    // 确认时快照的缺口前连续天数
  rescuedAt: number;
  ruleVersion: 1;
}
```

常量集中在 `src/lib/streak.ts`：
`STREAK_MIN_MINUTES=10`、`STREAK_RESCUE_MIN_MINUTES=20`、`STREAK_RESCUE_DAYS=2`、`STREAK_RESCUE_WINDOW_DAYS=3`、`STREAK_RESCUE_COOLDOWN_DAYS=14`、`STREAK_RESCUE_MIN_RUN=3`。

**UI 落点（首页零新增模块）**：
- 首页头部现有火焰按钮：`onOpenSettings` → 打开新组件 `StreakSheet`（底部弹层）：当前/最长连续、近 30 天格子、修复进度（1/2）、「接回」按钮（条件不满足时禁用并写原因）、接回历史。
- 不碰 `HOME_MODULES` / `DEFAULT_HOME_ORDER` / `settings.homeOrder` / 底部导航。
- 统计页的「连续学习」数字口径改为：`streak > 0` 显示天数，`0 且有过学习日` 显示「已断」，从没有记录才显示「未开始」。

**边界与坑**：
- 时区：现有 `computeStreaks` 用 `cursor -= 86400000` 回退，中国无 DST 但桌面用户可能在别的时区 → 改为复用 `addDaysTs`（`src/lib/time.ts`）。
- 未来日期：导入的脏数据可能有未来 `startedAt` → 状态计算只考虑 `<= 今天`。
- 性能：首页 `computeStreaks` 目前依赖 `[sessions, ts]`，`ts` 每秒变 → 新状态计算按 `dayKey(ts)` 记忆化，避免每秒 O(n)。

**测试**：新 `scripts/test-streak-rescue.mjs`（约 20 条）：无记录/今天没学/9 分钟边界/缺 1 天/缺 2 天/缺口前仅 2 天/17 分钟不进修复/20 分钟边界/修复 1-2/接回后 streak=前段+2/14 天冷却/补录后失效/跨零点按开始时间/接回前后 `sessions.length` 与总时长不变。

### 2.2 成就 / 里程碑

**最小集 10 个**（全部由真实记录派生；不设排行榜；**不设领取按钮**——没有奖励，领取是空按钮，违反「不放假按钮」）：

| id | 名称 | 判定 |
|---|---|---|
| `total-10h` / `total-50h` / `total-100h` | 累计学习 10 / 50 / 100 小时 | `Σ durationSec/60` |
| `days-30` / `days-100` | 学习日 30 / 100 天 | ≥10 分钟的学习日 |
| `streak-7` / `streak-30` | 最长连续 7 / 30 天 | 历史最长（不是当前连续） |
| `first-goal` | 第一个完成的目标 | `completedAt` 最早 |
| `goals-10` | 完成 10 个目标 | `completedAt` 计数 |
| `session-90m` | 单次学习 90 分钟 | `max(durationSec/60)` |

**明确不做**：连续 N 天达成每日目标（历史每日目标没存，硬做=假数据）、各科均衡、「今日超额/任务全完成」（与评价卡重复）、排名/超越比例/好友对比、早起/熬夜成就。

**落盘**：`AchievementUnlock { id, unlockedAt, evidence, backfilled?, ruleVersion:1 }`，顶层字段 `achievements`。
- `reconcile` 幂等：只追加、不删除、不改已解锁时间；判定在 `src/lib/achievements.ts`。
- 升级补记：hydrate 时若缺字段，按现有数据算一遍；能推算时刻的用证据时刻（累计时长跨阈值那段的 `endedAt` 等），否则 `Date.now()`；统一 `backfilled: true`，不弹「刚刚解锁」。
- 目标被改回 `todo` 后，已解锁成就不收回（账本语义）。

**UI**：统计页新增「成就」标签：顶部「已获得 N / 10」+ 固定顺序列表；已获得显示日期，未获得显示真实进度（如 `7h20m / 10h`）；不按进度排序、不做数字滚动动画。

**测试**：新 `scripts/test-achievements.mjs`（约 15 条）：各阈值边界、断签不解锁项消失、重复 reconcile 幂等、旧备份补记且 `backfilled`、导出导入往返一致、`resetAll` 清空、320/360 不横向溢出。

### 2.3 各科考试分数 vs 目标

**结论：不复用 Goal**。现有「成果目标」是一条数值进度（当前值→目标值），表达不了「多科目 × 多次考试 × 每次一个满分制」；硬塞会让目标模型变形。

**落点：统计页新标签「成绩」**（理由：成绩是记录 + 时间序列 + 均值，天然是统计语义；统计页已有「课程完成情况」这种「与学习时长无关 + 明确免责文案」的先例）。

**数据模型**：

```ts
interface ExamScore {
  id: string;
  subject: string;         // 与 Session.subject 同一套字符串
  examName: string;        // 期中 / 第一次月考
  date: string;            // 'yyyy-MM-dd'（与 CalendarEvent/ImportantDate 同约定）
  score: number | null;    // null = 缺考，不参与均值/最近一次/达标
  fullScore: number;       // 100 / 150 / 120；默认 100
  note?: string;
  createdAt: number;
}

interface SubjectScoreTarget {
  subject: string;
  targetScore: number;
  fullScore: number;       // 与目标对应的满分制
  updatedAt: number;
}
```

- **目标分按科目存一份长期目标**，不挂在每条记录上：目标是要画在趋势图上的**一条横线**，不是「每次录分时的心情」；先立志后考试也能显示。
- **必须有 `fullScore`**：105/150 与 95/100 直接比大小会得出「105 比 95 好」（实际 70% < 95%）。所有比较一律折成百分制比率，UI 同时显示「105 / 150 · 70%」。
- **缺考记 `null`，绝不记 0 分**（0 分会拉低均值，并在没参加考试时判「未达标」）。
- 补考 = 再写一条记录（同名 + note），不进分组模型。
- 未来日期可存，但不抢「最近一次」。

**计算**（`src/lib/examScores.ts` 纯函数）：`examRate` / `latestBySubject` / `scoreSummaries`（最近一次、目标、差距、均值、样本数、进步幅度）/ `trendSeries` / `sanitizeExamScores`。
口径：最近一次按 `date` 取；无目标时 `gap/met` 返回 `null`（不显示「差 0 分」）；均值用折合百分制并显示样本数。

**图表**：手写 SVG，不引图表库（`src/components/charts` 现状只有 `BarChart.tsx`）：
- `TrendChart`：单科折线 + 目标虚线 + 图例；y 轴固定 0–100；x 轴按记录序号等距（考试日期不规则，按时间比例会在小屏挤成一点）；空态不画假坐标系。
- `ScoreBars`：各科「最近一次 vs 目标」横条 + 目标刻度；达标 `--ok`、未达标 `--accent`。
- 颜色只用语义令牌；不做多科叠线（手机上会缠）。

**UI**：成绩卡顶部「+ 记录成绩」按钮；`ExamScoreSheet` 录入/编辑（两段式删除）；科目从现有课程/目标的 subject 取并去重；满分默认继承该科上次制式；卡内写免责句「成绩只是记录，不计入学习时长」。

**与既有「考试」概念边界**：`ImportantDate.kind === 'exam'`（倒计时）与 `CalendarEvent.tone === 'exam'`（日历标注）**不做自动关联**，文案上也不互相引流，避免误会它们会同步。

**落盘与兼容**：见 §2.4；`importSnapshot` 不经过 `migrate()`，旧备份缺字段必须显式 `?? []`。

**测试**：新 `scripts/test-exam-scores.mjs`：100/150 折合、缺考不拉低均值、目标=满分不 NaN、坏数据 sanitize、store 与 localStorage 分别断言、导入旧备份保留原 sessions/goals、录入后 sessions/goals 不变、`test-stats-tabs` 原样通过（概览数字不变）。

## 3. 第二批：1.4.x 深色对比度 + 无障碍

### 3.1 真实低对比在哪（调研结论）

- `audit-quality.mjs` 用真实像素量对比度，但 **`totalLow` 不参与退出码** —— 目前「基线只许升不许降」只是文档纪律，不是机器门禁。
- 现有 17 条低对比里 **3 条是禁用态假阳性**（祖先 `opacity-40`，WCAG 1.4.3 豁免），工具没查祖先 opacity。
- 真问题集中在两类：
  1. **用填充色当文字色**：16 处 `text-[var(--accent)]`、`.pill-ok/warn/bad` 的 `color: var(--ok/warn/bad)`；浅色主题下 `--ok` 压 `--ok-soft` 约 2.98:1、`--warn` 约 2.58:1、`--bad` 3.47:1。
  2. **半透明玻璃随亮背景漂移**：深色主题小字在亮背景区域会掉到 4.5 以下（lg 深背景灰度 >65 就临界）。

### 3.2 令牌级修复（低风险，先做）

| 新令牌 | 值 | 替换范围 |
|---|---|---|
| `--accent-text` | 浅 56%+黑 / 深 68%+白（= 现 `--accent-on-soft`） | 16 处 `text-[var(--accent)]`、`.pill-accent` |
| `--ok-text` / `--warn-text` / `--bad-text` / `--info-text` | 各自 60% + 黑（深色直接 alias 原色） | `.pill-ok/warn/bad`、所有 `bg-*-soft + text-*` 组合（约 25 处） |
| `--on-ok` | 浅色白字 / 深色深字 | `GoalItem` 的 `text-white` 勾选 |

另外：`DatesSection` 白字压 accent 的按钮改 `--primary-bg`；8 处静态色值（`text-white`、`bg-black/45` 等）收编成 `--scrim` / `--switch-knob` / `--hairline`；`StudyHeatmap` 里重写的热力梯度改为读 CSS 令牌。

**工具改造**（`audit-quality.mjs`）：
- 过滤「祖先 opacity 累计 <0.6」的禁用态；
- `totalLow` 纳入退出码（新参数 `--max-low`，从 17 起步，只许降）；
- 路由补 `checklist` / `settings/schedule`；
- 新 `scripts/audit-contrast-tokens.mjs`：1×1 canvas 解析 `color-mix`，12 主题×模式 × 6 文本令牌 × 表面，断言 ≥4.5（目标 4.8），写 `.preview/contrast-tokens.json` 基线，退步即 exit 1 —— **这才是「只许升不许降」的机器化落点**。

### 3.3 身份级改动（已拍板接受，逐主题截图后再提交）

- 浅色 `--text-tertiary` 0.56 → **0.62**；深色 0.60 → **0.66**（130 处小字整体略重，层级仍可分）。
- 深色玻璃 `--surface` alpha 适度上调（解决小字随亮背景漂移），具体值以截图对比定。

## 4. 第三批：1.5.0 学习提醒 / 通知

**现状**：全项目零系统通知；`package.json` 无插件；`AndroidManifest.xml` 只有 `INTERNET`；`src/` 里「通知/提醒」全是更新提示与文案。

### 4.1 方案：官方插件（锁版本）

- 依赖：`"@capacitor/local-notifications": "8.3.1"`（**不加 `^`**：8.3.0 起行为刚变过——`schedule()` 自动申请权限、结构化错误码、`isExactNotification` 默认 `true`）。
- `npx cap sync android` 自动改三处（`capacitor.plugins.json`、`capacitor.settings.gradle`、`capacitor.build.gradle`），**不手写**。
- 备选（若不想加依赖）：自写 `AlarmManager` + `NotificationManager` 插件，沿用 `WidgetBridgePlugin` 注册方式；代价是开机恢复、时区变更、PendingIntent 不可变标志等都要自己踩。**不推荐**。

### 4.2 触发三件套 + 文案

统一约束：标题 ≤12 字、正文 ≤40 字、**无感叹号**、不比较、不承诺；同类每天最多 1 次；每条都能单独关。

| 提醒 | 触发 | 默认 | 跳过条件 | 文案示例 |
|---|---|---|---|---|
| 学习开始 | 当天 `studyFrom` 到点，默认只在有课日（`resolveDay().hasClass`） | 开 | 已在计时 / 今天已有学习记录 / 放假日 | 标题「学习窗口开始了」正文「现在是 17:40，今天的学习窗口到 22:30。先做最小的一件就行。」 |
| 计时到点 | `targetMinutes` 到点：前台用页内提示 + 震动；**切后台才发系统通知**，回前台撤销 | 开 | 无目标时长 | 标题「到设定时长了」正文「这一段落够长了，可以收尾，也可以继续。记得保存这次记录。」 |
| 睡前目标未达成 | `sleepTime - 30min`，`todayProgress < 100%`；**今天 0 分钟默认不发** | 开 | 已达标 / 已有计时 / 当天已发过 | 标题「今天还差一点」正文「离今天的目标还有 40 分钟。睡前做一点也算数，做不完也没关系。」 |
| 火花要断 | 睡前，`streak > 0` 且今天 <10 分钟 | **关**（opt-in） | 今天已学满 10 分钟 | 标题「还差 10 分钟」正文「今天再学 10 分钟，连续第 7 天就接上了。不想学也没关系，明天还在。」 |

### 4.3 设置项

新增 `ReminderSettings`（放 `Settings.reminders?`），`normalizeSettings` 里**深合并 + 逐字段校验**（照 `glass` 的处理，否则旧备份半个对象会让开关变 `undefined`）：

```ts
interface ReminderSettings {
  enabled: boolean;              // 总开关，默认 false：不在首启弹权限
  studyStart: boolean;           // 默认 true（随总开关）
  schoolDaysOnly: boolean;       // 默认 true：只在有课日提醒
  timerEnd: boolean;             // 默认 true
  dailyGoal: { enabled: boolean; leadMin: number; remindWhenNone: boolean }; // true / 30 / false
  streak: { enabled: boolean; leadMin: number };                              // false / 30
}
```

设置页新增第 7 个标签「提醒」（`Bell` 图标）；必须同时改 `TabId` 与 `TAB_ALIAS`，否则深链会静默回落到外观页。

### 4.4 权限与降级（诚实性）

- 总开关打开时才 `checkPermissions()` / `requestPermissions()`（Android 13+ `POST_NOTIFICATIONS`）；Android 12 及以下直接 granted。
- **`isExactNotification: false` 必须显式传**：8.3.0 默认 `true`，会在 API 31+ **直接把用户弹到系统「闹钟和提醒」设置页**。只有用户主动开「精准提醒」才对计时到点用 `true`。
- 精确闹钟被拒 → 全部降级为非精确，UI 写「可能晚几分钟」，**不假装精准**。
- 权限被拒 → 开关回弹 + 文字指引，**不假装开启**（铁律 11：以可观测真实状态为准）。
- Web / PWA：不排任何通知；设置页禁用开关并说明「网页版关掉页面后收不到提醒」，保留已存设置等回 App 生效。所有插件调用走 `Capacitor.isNativePlatform()` + try/catch（照 `widgetBridge.ts`），失败不挡主流程。
- 诚实性：**force-stop 后 AlarmManager 闹钟会被系统清掉，不保证响**；Doze 下 `allowWhileIdle` 也只有 9 分钟粒度。产品文案不写「一定提醒」。

### 4.5 排程实现

- 滚动 **7 天窗口 + 一次性通知**（不用 `repeats`：要按星期几/放假逐日决定发不发）。
- id 分段：`1000+0..6` 学习开始、`1100+0..6` 每日目标、`1200+0..6` 火花、`1300` 计时结束；重排前先 `cancel` 本段。
- 重排时机：hydrate 后、回前台（`visibilitychange`）、设置变更（`useStore.subscribe` + 节流）、`importSnapshot`/`resetAll` 之后。
- 计时结束：用 `elapsedMs(timer, now)` 算「还差多少毫秒」再排一次性通知，不要自己推导墙钟；计时中切后台排、回前台撤；App 被杀后恢复且已超时 → **不补系统通知**，只在计时页显示一次「已超过设定时长」。
